Torus and oloid: from NURBS to a printable STL#

These two scripts each construct one object with native nurbspy classes, export a binary STL file, check the reloaded mesh, and open the original NURBS construction in the editor with its control net and background grid. Trimesh and NetworkX are standard dependencies. PNG export uses an isolated headless browser; see the figure guide for browser setup.

Run the example#

From the repository root:

python demos/02_surfaces/21_stl_torus.py
python demos/02_surfaces/22_stl_oloid.py

The default print preset writes torus_print.stl under demos/02_surfaces/output/21_stl_torus/ and oloid_print.stl under demos/02_surfaces/output/22_stl_oloid/. Each script reloads its STL with Trimesh and checks that the mesh is closed and consistently oriented. The editor shows the editable NURBS rather than a frozen mesh overlay. These STL files describe the initial construction, before interactive edits.

python demos/02_surfaces/21_stl_torus.py --quality preview
python demos/02_surfaces/22_stl_oloid.py --quality fine --no-show
python demos/02_surfaces/21_stl_torus.py --output-dir my_stl_files

STL has no units: select millimetres when importing these files into a slicer. --no-show writes and validates the mesh without opening the editor. For matching PNG and offline interactive HTML files, use the separate exporter:

python docs/export_demo_figures.py --only 02_surfaces/21_stl_torus 02_surfaces/22_stl_oloid

Both formats are written alongside each STL in its corresponding output folder. The Figure guide describes the public export methods.

Geometry and dimensions#

Torus. make_torus(major_radius=30, minor_radius=10) makes an exact rational circular profile with CircularArc, then revolves it through \(2\pi\) with NurbsSurfaceRevolution. Radii are in millimetres. The major radius is the distance from the rotation axis to the tube centreline; the minor radius is the tube radius. The resulting dimensions are \(80\times80\times20\) mm. Keep \(R>r>0\) for a ring torus. Here \(u\) follows the revolution and \(v\) follows the tube profile.

Oloid. make_oloid(radius=20, boundary_points=181) uses equal-radius circles in perpendicular planes, whose centres are one radius apart. Paired contact points define two native NurbsSurfaceRuled patches. The approximate dimensions are \(60\times40\times40\) mm. The boundaries are sampled degree-one NURBS curves: this is an approximation to an oloid, not an exact analytic representation. Dimensions are rounded: for example, the preview mesh spans about 39.9959 mm in \(y\), slightly below the ideal 40 mm. Here \(u\) follows the paired boundary points and \(v\) runs along each straight ruling.

The symmetric construction needs an odd boundary_points count of at least five. More boundary points improve the underlying curved-boundary approximation. Increasing export nu alone cannot recover curvature missing from those piecewise-linear boundaries.

Every tessellation and export control#

Parameter

API default

Meaning and how to choose it

nu

80

Integer regular sample count along \(u\), at least two. Increase where geometry changes strongly in this direction. Torus: around the major circle. Oloid: along the curved boundaries.

nv

30

Integer regular sample count along \(v\), at least two. Torus: around the tube. Oloid: across the straight rulings, where fewer samples are normally needed. Bilinear cells can still be slightly warped, so check refinement rather than assuming every quad is planar.

require_closed

False

Export-only switch. Set True for these solid-printing examples. Rejects open edges and requires consistent winding, positive volume, and one face-connected shell. It does not cap openings or detect self-intersections.

weld_tolerance

None

Export-only approximate seam-merging length in the same units as the coordinates. None selects \(10^{-10}\) times the largest extent. It controls vertex merging, not geometric approximation accuracy.

path

Required

Output .stl path. The exporter writes binary STL and returns a Path. The demo creates its output directory first.

surface.tessellate(nu=..., nv=...) and nrb.tessellate_surfaces(patches, nu=..., nv=...) return NumPy vertices and faces. They accept only the two sampling controls: welding and closed-shell checks belong to export. Knot breaks are included automatically, so the actual number of samples can exceed the requested regular counts. Before seam/degenerate cleanup, a grid typically produces \(2(N_u-1)(N_v-1)\) triangles per patch. Doubling both sample counts therefore roughly quadruples the mesh size.

The plotting arguments Nu and Nv are capitalized and independent of the lowercase export arguments. In the demo, native model plots use Nu=73, Nv=41; changing those values changes the display, not the STL.

Choose the settings explicitly#

For a single torus surface:

torus = make_torus(major_radius=30, minor_radius=10)
vertices, faces = torus.tessellate(nu=129, nv=65)  # inspect without writing
path = torus.export(
    "torus.stl",
    nu=129,
    nv=65,
    require_closed=True,
    weld_tolerance=None,
)

For the two-patch oloid, use the shared multi-patch exporter so that it can merge the seams and validate the complete object:

patches = make_oloid(radius=20, boundary_points=181)
path = nrb.export_stl(
    patches,
    "oloid.stl",
    nu=181,
    nv=5,
    require_closed=True,
    weld_tolerance=None,
)

These snippets use the builders from the example script and import nurbspy as nrb. The script’s QUALITY dictionary is the single place to change preset sampling and oloid boundary density.

Seam merging is different from mesh accuracy#

Keep weld_tolerance=None initially. Its default is about \(8\times10^{-9}\) mm for the torus and \(6\times10^{-9}\) mm for the oloid: intended for numerical seam noise, not manufacturing gaps. If independently generated, otherwise compatible seams differ by tiny round-off errors, an explicit value such as weld_tolerance=1e-7 mm can be tried after checking the actual gap. Keep it much smaller than the smallest feature and mesh-edge spacing that must survive. Increasing it indiscriminately can merge real features.

Trimesh merges using decimal rounding of normalized coordinates. Consequently, this value is an approximate rounding scale, not a guaranteed Euclidean merge radius. Values must be at least \(10^{-15}\) times the object’s largest extent and smaller than that extent. Corresponding patch boundaries still need matching sample locations; this parameter cannot repair incompatible parameterizations or missing faces.

The default STL sizes are about 800 KiB and 141 KiB. The script prints actual triangle counts, file sizes, bounding dimensions, and enclosed volume after reload. The torus has analytic volume \(2\pi^2Rr^2\approx59{,}217.6\) mm\(^3\); observed STL volumes were about 57,327.9, 59,098.0, and 59,187.7 mm\(^3\) for the three presets. The progression gives a useful convergence check, but volume agreement alone does not bound local surface error.

Start with preview to inspect orientation and shape. Compare print with fine, checking silhouettes, critical dimensions, and small features against your required tolerance. Count-based tessellation is not adaptive and has no chord-error setting. A larger or more curved model may need more samples than these examples. For the oloid, refine boundary points as well as export sampling.

Importing into a slicer#

STL carries no units. These examples use millimetre-sized coordinates; select millimetres on import and check the dimensions above. Layer height, nozzle size, infill, print orientation, and support generation are slicer settings, not nurbspy tessellation controls. A closed mesh does not establish that a particular orientation can be printed without supports.

The examples verify watertightness and positive volume after reading the files back, but do not perform general self-intersection checks. Export validation supports one connected shell; separate solids should be exported separately, and nested cavity shells are not supported by require_closed=True. STL uses float32 coordinates, so keep objects near the origin and avoid coordinate offsets that overwhelm small features.

Complete scripts#

"""Export a closed torus STL, then edit its original NURBS construction.

Reload and validate the STL using Trimesh. The editor opens one construction
with its control net and background grid. STL coordinates are millimetres;
the file records the initial geometry before interactive edits.
"""

import argparse
from pathlib import Path

import numpy as np
import trimesh
import nurbspy as nrb

QUALITY_LEVEL = "print"  # STL mesh sampling: "preview", "print", or "fine".
OUTPUT = Path(__file__).resolve().parent / "output" / Path(__file__).stem
# Samples in each STL parameter direction; these do not control display quality.
QUALITY = {"preview": (33, 17), "print": (129, 65), "fine": (257, 129)}


def make_torus(major_radius=30.0, minor_radius=10.0):
    """Exact ring torus: major radius is measured to the tube centreline [mm]."""
    if (
        not np.isfinite([major_radius, minor_radius]).all()
        or not major_radius > minor_radius > 0
    ):
        raise ValueError("Use finite radii with major_radius > minor_radius > 0")
    profile = nrb.CircularArc(
        nrb.Point(major_radius, 0, 0),
        np.array([1.0, 0, 0]),
        np.array([0.0, 0, 1]),
        minor_radius,
        0,
        2 * np.pi,
    ).NurbsCurve
    return nrb.NurbsSurfaceRevolution(
        profile,
        nrb.Point(0, 0, 0),
        np.array([0.0, 0, 1]),
        0,
        2 * np.pi,
    ).NurbsSurface


def run_demo(output_dir, quality="print", show=True):
    """Write one closed STL and return its editable NURBS figure."""
    settings = QUALITY[quality]
    patches = [make_torus()]
    output_dir = Path(output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)
    path = output_dir / f"torus_{quality}.stl"
    # The exporter merges coincident seam vertices with its scale-relative default.
    options = dict(nu=settings[0], nv=settings[1], require_closed=True)
    patches[0].export(path, **options)
    mesh = trimesh.load_mesh(path)
    if not mesh.is_watertight or not mesh.is_volume:
        raise RuntimeError(
            "The reloaded STL must be a closed, consistently oriented volume"
        )
    dimensions = np.ptp(mesh.bounds, axis=0)
    print(
        f"{path.name}: {len(mesh.faces):,} triangles; {path.stat().st_size / 1024:.1f} KiB; "
        f"size {dimensions.round(2)} mm; volume {mesh.volume:.1f} mm^3"
    )
    figure = nrb.Figure(
        patches[0],
        name="Torus patch 1",
        title="Torus: NURBS construction for STL export",
        display=dict(control_points=True, control_polygon=True, grid=True),
    )
    for index, patch in enumerate(patches[1:], start=2):
        figure.add(patch, name=f"Torus patch {index}")
    if show:
        figure.edit()
    print("STL has no units: select millimetres in your slicer.")
    return figure


def main(show=True):
    return run_demo(OUTPUT, quality=QUALITY_LEVEL, show=show)


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--quality", choices=QUALITY, default=QUALITY_LEVEL)
    parser.add_argument("--output-dir", type=Path, default=OUTPUT)
    parser.add_argument(
        "--no-show", action="store_true", help="Export without opening the editor"
    )
    args = parser.parse_args()
    run_demo(args.output_dir, quality=args.quality, show=not args.no_show)

"""Export a closed oloid STL, then edit its original NURBS construction.

Reload and validate the STL using Trimesh. The editor opens one construction
with its control net and background grid. STL coordinates are millimetres;
the file records the initial geometry before interactive edits.
"""

import argparse
from pathlib import Path

import numpy as np
import trimesh
import nurbspy as nrb

QUALITY_LEVEL = "print"  # STL mesh sampling: "preview", "print", or "fine".
OUTPUT = Path(__file__).resolve().parent / "output" / Path(__file__).stem
# Samples in each STL parameter direction; these do not control display quality.
QUALITY = {
    "preview": (61, 3, 61),
    "print": (181, 5, 181),
    "fine": (361, 9, 361),
}


def make_oloid(radius=20.0, boundary_points=181):
    """Two ruled NURBS patches with piecewise-linear sampled boundaries [mm]."""
    if not np.isfinite(radius) or radius <= 0:
        raise ValueError("radius must be finite and positive")
    if (
        isinstance(boundary_points, (bool, np.bool_))
        or not isinstance(boundary_points, (int, np.integer))
        or boundary_points < 5
        or boundary_points % 2 == 0
    ):
        raise ValueError("boundary_points must be an odd integer of at least five")
    # Equal-radius circles in perpendicular planes; centres one radius apart.
    # Cluster samples near the ends and keep a symmetric grid for matching seams.
    theta = np.pi - 2 * np.pi / 3 * np.cos(np.linspace(0, np.pi, boundary_points))
    c, s = np.cos(theta), np.sin(theta)
    cos_phi = np.clip(c / (1 - c), -1, 1)
    sin_phi = np.sqrt(1 - cos_phi**2)
    cos_phi[[0, -1]], sin_phi[[0, -1]] = 1.0, 0.0  # exact common seam endpoints
    first = nrb.NurbsCurve(
        [nrb.Point(radius * (x - 0.5), radius * y, 0) for x, y in zip(c, s)],
        degree=1,
    )
    patches = []
    for sign in (-1, 1):
        second = nrb.NurbsCurve(
            [
                nrb.Point(radius * (0.5 + x), 0, sign * radius * z)
                for x, z in zip(cos_phi, sin_phi)
            ],
            degree=1,
        )
        patches.append(nrb.NurbsSurfaceRuled(first, second).NurbsSurface)
    return patches


def run_demo(output_dir, quality="print", show=True):
    """Write one closed STL and return its editable NURBS figure."""
    settings = QUALITY[quality]
    patches = make_oloid(boundary_points=settings[2])
    output_dir = Path(output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)
    path = output_dir / f"oloid_{quality}.stl"
    # The exporter merges coincident seam vertices with its scale-relative default.
    options = dict(nu=settings[0], nv=settings[1], require_closed=True)
    nrb.export_stl(patches, path, **options)
    mesh = trimesh.load_mesh(path)
    if not mesh.is_watertight or not mesh.is_volume:
        raise RuntimeError(
            "The reloaded STL must be a closed, consistently oriented volume"
        )
    dimensions = np.ptp(mesh.bounds, axis=0)
    print(
        f"{path.name}: {len(mesh.faces):,} triangles; {path.stat().st_size / 1024:.1f} KiB; "
        f"size {dimensions.round(2)} mm; volume {mesh.volume:.1f} mm^3"
    )
    figure = nrb.Figure(
        patches[0],
        name="Oloid patch 1",
        title="Oloid: NURBS construction for STL export",
        display=dict(control_points=True, control_polygon=True, grid=True),
    )
    for index, patch in enumerate(patches[1:], start=2):
        figure.add(patch, name=f"Oloid patch {index}")
    if show:
        figure.edit()
    print("STL has no units: select millimetres in your slicer.")
    return figure


def main(show=True):
    return run_demo(OUTPUT, quality=QUALITY_LEVEL, show=show)


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--quality", choices=QUALITY, default=QUALITY_LEVEL)
    parser.add_argument("--output-dir", type=Path, default=OUTPUT)
    parser.add_argument(
        "--no-show", action="store_true", help="Export without opening the editor"
    )
    args = parser.parse_args()
    run_demo(args.output_dir, quality=args.quality, show=not args.no_show)
